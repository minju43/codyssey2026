# Mini NPU Simulator

인공지능 가속기(NPU)의 핵심 연산인 **MAC(Multiply-Accumulate)** 원리를 외부 수치 연산 라이브러리 없이 순수 Python 반복문으로 구현한 패턴 판별 시뮬레이터입니다.

---

## 1. 실행 방법

1. **개발 환경**: Python 3.8 이상 (표준 라이브러리 `json`, `time`, `os`, `typing`만 사용)
2. **파일 구성**: `main.py`와 `data.json`을 동일한 디렉터리에 배치합니다.
3. **실행 명령어**:
   ```
   python3 main.py
   ```
4. **모드 선택**:
   - `1` 입력: 콘솔에서 3×3 필터 2개(A, B)와 3×3 패턴을 공백으로 구분해 입력하고 점수, 판정 결과, 평균 연산 시간을 확인합니다.
   - `2` 입력: `data.json`에서 크기별 필터(`size_5`, `size_13`, `size_25`)와 패턴을 로드하여 일괄 판정(PASS/FAIL), 크기별 성능 분석, 보너스 1차원 최적화 비교 및 결과 요약을 출력합니다.

---

## 2. 구현 요약

### 2-1. 핵심 기능 및 MAC 점수 해석 원리
- **MAC 연산 흐름 (`입력 → 위치별 곱셈 → 누적 합산 → 점수 반환`)**:
  - NumPy 등 외부 라이브러리 없이 N × N 크기의 입력 패턴과 필터의 동일 위치 `(i, j)` 원소를 곱한 뒤 누적 합산하는 이중 반복문(`mac_2d`)으로 구현했습니다.
- **MAC 점수의 의미 (점수 증가 = 패턴-필터 유사도 증가)**:
  - MAC 연산은 수학적으로 두 행렬을 1차원으로 펼쳤을 때의 **내적(Inner Product)**과 같습니다. 입력 패턴에서 값이 활성화된 위치(`1`)와 필터가 감지하려는 핵심 특징 위치(`1` 또는 높은 가중치)가 정확히 겹칠수록 `양수 × 양수` 항이 많이 누적되어 총점이 커집니다. 반대로 형태가 어긋나면 `0`과 곱해져 점수에 기여하지 못합니다.
  - **예시 (3×3 십자가 패턴 입력 시)**: 십자가 필터와는 5개 위치가 모두 일치해 **5.0점**을 얻지만, X 필터와는 중앙 1개 위치만 겹쳐 **1.0점**에 그치므로 높은 점수를 기록한 필터를 입력 패턴의 정체로 판정합니다.

### 2-2. 라벨 정규화 및 새 라벨 확장 절차
- **라벨 정규화(Normalization)**:
  - `data.json`에서 혼용되는 필터 키(`cross`, `x`)와 정답 라벨(`+`, `x`)을 입력 단계에서 표준 라벨(`Cross`, `X`)로 통일하여 문자열 표기 차이로 인한 비교 오류를 방지했습니다.
- **새 라벨(예: `Circle` / `O`) 추가 확장 절차**:
  1. **정규화 규칙 추가 (`main.py` > `normalize_label`)**: 새로운 입력 표기(예: `"o"`, `"circle"`)를 표준 라벨(`"Circle"`)로 매핑하는 분기문을 추가합니다.
  2. **필터 로드 검증 확장 (`main.py` > `run_mode_json_analysis`)**: 필수 로드 필터 검사 조건(`"Cross"`, `"X"`)에 새 표준 라벨(`"Circle"`)을 포함하고, 다중 필터 중 최고 점수 및 `epsilon` 이내 동점 여부를 비교하도록 판정 로직을 확장합니다.
  3. **데이터셋 및 테스트 케이스 등록 (`data.json`)**: `filters`의 각 `size_N` 아래에 새 필터 행렬을 추가하고, `patterns`에 해당 `expected` 라벨을 가진 검증 케이스를 작성해 회귀 테스트를 수행합니다.

### 2-3. 부동소수점 및 동점 비교 정책 (Epsilon Policy)
- 실수 누적 연산 시 발생하는 이진 부동소수점 오차를 보정하기 위해, 두 필터 점수의 차이가 `1e-9` 미만(`abs(score_a - score_b) < 1e-9`)이면 어느 한쪽을 선택하지 않고 동점 처리했습니다.
- **모드별 동점 출력 정책**:
  - **모드 1 (사용자 입력)**: 직관적인 한글 안내를 위해 `"판정 불가"` 출력
  - **모드 2 (`data.json` 분석)**: 표준 영문 스키마 일관성을 위해 `"UNDECIDED"` 출력 (기대값이 `Cross` 또는 `X`인 경우 `FAIL`로 집계)

### 2-4. 보너스 기능 구현
- **메모리 접근 최적화**: 2차원 배열을 길이 N²의 1차원 리스트로 평탄화(`flatten_matrix`)하여 단일 루프로 연산하는 `mac_1d`를 구현하고 2D 방식과 속도를 비교했습니다.
- **패턴 생성기**: 임의의 크기 N에 대해 표준 `Cross`, `X` 행렬을 자동 생성하는 `generate_pattern` 함수를 구현해 3×3 성능 측정에 활용했습니다.

## 3. 결과 리포트

### 3-1. 테스트 결과 및 실패 원인 분석
- **테스트 요약**: 총 6개 테스트 중 **통과 3개 (`size_5_2`, `size_13_1`, `size_25_2`)**, **실패 3개 (`size_5_1`, `size_13_2`, `size_25_1`)**
- **원인 분류 및 진단**:
  1. **데이터/스키마 검증**: `data.json`의 모든 필터와 패턴은 키에서 추출한 크기 N과 실제 2차원 배열의 행/열 크기가 일치했으며, 라벨 정규화(`+` → `Cross`, `x` → `X`)가 정상 적용되어 스키마나 표기 불일치로 인한 오류는 발생하지 않았습니다.
  2. **수치 비교(부동소수점 오차 및 동점) 문제**: 실패한 3개 케이스는 모두 로직 오류가 아니라 **필터 가중치 설계와 허용오차(`1e-9`) 동점 판정 정책**에 의한 결과입니다.
     - **`size_5_1` (`Cross: 0.9` vs `X: 0.8999999999999999`)**: `0.1`을 9번 누적 합산하는 과정에서 IEEE 754 부동소수점 오차가 발생해 `0.9`보다 미세하게 작은 값이 도출되었습니다. `1e-9` 허용오차 정책이 정상 작동하여 오분류 대신 `UNDECIDED`로 판정되었고, 기대값(`X`)과 달라 `FAIL`로 집계되었습니다.
     - **`size_13_2` (`Cross: 7.499999999999997` vs `X: 7.5`)**: `0.3`을 25번 더한 `Cross` 점수가 부동소수점 누적 오차로 `7.499999999999997`이 되었으나, 허용오차 범위(`3e-15 < 1e-9`) 이내이므로 정확히 동점(`UNDECIDED`) 처리되었습니다.
     - **`size_25_1` (`Cross: 4.9` vs `X: 4.899999999999999`)**: 정중앙 가중치(`4.9`)와 대각선 49칸 합(`4.899999999999999`)의 차이가 허용오차 이내이므로 동점(`UNDECIDED`) 처리되어 기대값(`X`) 대비 `FAIL`로 분류되었습니다.

### 3-2. 성능 분석 및 시간 복잡도 O(N²)
| 패턴 크기 (N × N) | 평균 연산 시간 (ms) | 총 곱셈-누적 연산 횟수 (N²) |
| :--- | :---: | :---: |
| **3 × 3** | 0.0013 ms | 9 |
| **5 × 5** | 0.0037 ms | 25 |
| **13 × 13** | 0.0121 ms | 169 |
| **25 × 25** | 0.0396 ms | 625 |

- **시간 복잡도 근거**:
  - MAC 연산은 가로 N, 세로 N 크기의 2차원 배열 모든 원소를 순회하며 곱셈 1회와 덧셈 1회를 수행하므로 핵심 연산 횟수는 `N × N = N²`에 정확히 비례합니다. 따라서 시간 복잡도는 **O(N²)** 입니다.
  - 실측 결과에서도 데이터 크기가 `3×3`(9회) → `5×5`(25회) → `13×13`(169회) → `25×25`(625회)로 커짐에 따라 평균 연산 시간이 `0.0013 ms` → `0.0037 ms` → `0.0121 ms` → `0.0396 ms`로 급격히 증가했습니다. 특히 `3×3`에서 `25×25`로 길이가 약 8.3배 증가할 때 연산 횟수는 약 69.4배(`625 / 9`), 실행 시간은 약 30.5배 증가하며 N²에 비례하는 추세를 보입니다.
- **보너스 메모리 접근 최적화 결과 (`25×25`, 100회 평균)**:
  - 2차원 중첩 리스트(`mac_2d`): `0.0348 ms` / 1차원 평탄화 리스트(`mac_1d`): `0.0327 ms`
  - 2차원 배열의 이중 인덱스 참조(`pattern[i][j]`)를 1차원 연속 접근(`flat_pattern[i]`)으로 단순화함으로써 반복문 오버헤드가 줄어 약 6%의 실행 시간 단축을 확인했습니다.

### 3-3. 대규모 연산(1000 × 1000) 이슈 및 CPU vs NPU 병목 분석
- **대규모(1000 × 1000) 처리 시 발생 문제 및 우선 최적화 방안**:
  - **시간·메모리 문제**: `N = 1000`일 때 필터 1개당 연산 횟수는 `1000² = 1,000,000`회로, `25×25`(625회) 대비 **1,600배** 급증합니다. 순수 Python 이중 리스트 구조에서는 수백만 개의 `float` 객체 포인터 간접 참조로 인해 CPU 캐시 미스(Cache Miss)와 인터프리터 루프 오버헤드가 극심해집니다.
  - **우선 최적화 방안**:
    1. **메모리 평탄화 및 연속 배치 (1D Flattening)**: 2차원 중첩 구조를 1차원 연속 메모리로 변환해 공간 지역성(Spatial Locality)을 확보합니다.
    2. **블록(타일링, Tiling) 분할 처리**: `1000 × 1000` 전체를 한 번에 순회하지 않고 CPU L1/L2 캐시 크기에 맞는 작은 블록(예: `32×32`) 단위로 잘라 연산해 캐시 적중률을 극대화합니다.
    3. **벡터화(SIMD) 및 멀티스레딩**: C 기반 연속 배열(NumPy 등)의 SIMD 명령어로 한 클럭에 여러 원소를 동시 곱셈하거나, 행 단위로 스레드를 분할해 병렬 처리합니다.
- **CPU 직렬 처리 vs NPU 병렬 처리 병목 분석**:
  - **CPU 병목 (제어 중심 · 직렬/폰 노이만 병목)**: CPU는 범용 분기 처리와 복잡한 제어 로직에 최적화되어 있어 MAC 연산을 순차적으로 처리합니다. 대규모 행렬 연산 시 매 곱셈·덧셈마다 메인 메모리(DRAM)에서 레지스터로 피연산자를 반복적으로 가져오고(Fetch) 다시 저장하는 **메모리 대역폭 병목(Memory Wall)** 이 발생해 연산 장치가 데이터를 기다리며 유휴 상태에 빠집니다.
  - **NPU 해결 구조 (연산 중심 · 대규모 병렬/데이터 재사용)**: NPU는 수천 개의 MAC 연산기(PE, Processing Element)를 **시스톨릭 어레이(Systolic Array)** 형태로 격자 배치해 수천 번의 곱셈-누적을 단일 클럭 주기에 동시 수행합니다. 또한 한 번 로드한 필터 가중치와 입력 데이터를 인접한 MAC 유닛 간에 직접 전달(Data Reuse)하여 외부 메모리 접근 횟수를 획기적으로 줄임으로써 대규모 AI 추론의 병목을 해소합니다.
